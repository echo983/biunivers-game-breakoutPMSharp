## 3. 技术方案

### T1 真穿透（多砖连穿）

**问题**：碰撞事件在求解器后触发，球先被反射、砖块后移除 → 当前是"击破 + 反射"。

**方案**（最简，无需传感器）：
- 每个物理子步记录 `vel_before`（完整速度向量，含方向）。
- 球-砖块 `Started` 且冲击 ≥ 阈值 → 移除砖块后，`set_linvel(vel_before, true)`。
- 求解器已把球反射为 `v'`；恢复 `vel_before` 等价于再反射一次，抵消反弹 → 球沿原方向
  继续穿过砖块位置。
- 多砖连穿：下一子步 `vel_before` 仍是原方向 → 击穿下一块。
- 低于阈值：保持现状（砖块反弹，restitution 1.0）。

**验收**：≥阈值时一次撞击连续击穿同排 2+ 砖（仿真验证）；<阈值时球被反弹、砖不破。

**注意**：`vel_before` 需在子步开始前采样（现已有 `approach_speed`，扩展为完整向量）。

### T2 传送门目标（挖掘型）

**方案**：
- **关卡定义结构**：`Level { layout: 砖阵模式, objective: Objective, balls: u32 }`。
  `Objective::ClearAll`（v1 现有）| `Objective::Portal { row, col }`（传送门位于指定砖
  格之后）。
- **传送门**：位于砖阵后方（如顶行中列），覆盖砖未破坏前不可见/不可达；覆盖砖破坏后
  暴露（渲染切换为发光圆盘）。
- **命中判定**：传送门为 `sensor(true)` 碰撞体（不产生物理响应），`Started` 且对端是球
  → 目标完成 → Victory（胜利文案区分目标类型）。
- **胜利条件分支**：`Portal` 目标不要求清空全部砖块（符合 v0.1 §13 "不要求清空全部环境"）。

**验收**：砖阵中埋设传送门的关卡，清出路径后球射入即胜利；砖块未清完也成立；ClearAll
关卡行为与 v1 一致。

### T3 无接触环境扰动

**方案**：
- 计时 `contact_timer`：球-球拍 / 球-砖块 任一 `Started` 时清零。
- 超时（如 **4.0s**）且状态 Play → 施加轻微扰动：沿球当前运动方向垂直叠加一个小横向
  速度（如 ±40 px/s，方向取当前 `vel.x` 的相反倾向或按时间奇偶），打破稳定轨道。
- 扰动强度远低于增压量级，不显著改变手感；防止"顶带滞留/侧墙往返"无限循环。
- 上限保护：扰动本身受 `MAX_BALL_SPEED` 钳制。

**验收**：构造"顶带滞留"场景（仿真），球在 4s 后脱离滞留区；正常对局中感觉不到明显异常。

### T4 硬砖受损视觉

**方案**：
- 渲染器新增 `update_brick_color(index, color)`（`move_brick` 同款 uniform 重写路径）。
- 硬砖（HP2）受第一击后颜色加深/变灰（受损态）；第二击消失。
- 软/普通砖 HP1 无中间态，不受影响。

**验收**：硬砖被 ≥1100 冲击一次后外观变化，再击一次消失。

## 4. 关卡与内容

- v1.1 提供 **2 个关卡**：
  - 关卡 1：ClearAll（复用 v1 布局，微调列/行以容纳传送门预留位）。
  - 关卡 2：Portal（顶排中央埋传送门，覆盖 1×2 砖）。
- 胜利 → 进入下一关（保留球拍与当前球数？——决定：**保留球拍，重置球数**）；末关胜利
  → 通关结算（"全部通关"覆盖层）。

## 5. 验证方法

1. 原生探测（同 v1 方法）：T1 连穿、T3 扰动脱离、阈值边界。
2. 浏览器/桌面实测：两关各通一遍；最小窗口（360×400）下传送门可见。
3. 回归：v1 全部行为不变（ClearAll 关卡、三球拍、增压节奏、HUD）。
4. 规范性：冻结协议未触碰、无 secret、CHANGELOG 登记 0.6.0、README/design 更新。

## 8. 风险

- **T1 抵消反射的边角**：球同时命中砖块与墙（角落）时恢复 `vel_before` 可能让球进入墙内
  ——需在恢复后做一次位置 clamp 或仅当命中砖块时恢复。
- **T2 传送门可达性**：若覆盖砖在球速不足时不可破，关卡可能不可通关——传送门覆盖砖
  配置为软砖或普通砖，保证 3-4 颠后可达。
- **T3 扰动感**：强度需手感实验（40px/s 为初值，记入参数表）。
