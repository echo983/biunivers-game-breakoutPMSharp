# Biunivers Breakout — 第一个完整版本设计（v1）

> 分支：`feat/v1-first-version`
> 当前版本：0.5.2（分支末态；历史见 `CHANGELOG.md`）
> 依据：`docs/design-v0.1.md` §17 最小可玩原型，收束为 v1 可交付范围。

## 1. v1 范围

| 设计草案条目 | v1 是否包含 | 说明 |
|---|---|---|
| 球 ×1 种 | ✅ | 现有 |
| 球拍 ×3（滑板/橄榄球/碗） | ✅ | 现有，几何差异即控制语言 |
| 砖块 ×3 种（软/普通/高阻力） | ✅ | 本版核心新增 |
| 重力/刚体/曲面碰撞/速度增压 | ✅ | 现有（增压 1.30 已标定） |
| 高速穿透 | ⚠️ 未实现（如实说明） | 破砖时球仍会被**反射**（经典 Breakout 行为）：碰撞事件在求解器之后触发，球先反弹、砖块后移除。"不消耗球速"成立（restitution 1.0），但**多砖连穿不成立**。真穿透（传感器+手动轨道）留 v1.1 |
| 目标：清除型 | ✅ | 清空全部砖块 → 胜利 |
| 目标：挖掘型（传送门） | ❌ | v1.1 |
| 固定球数 | ✅ | 5 球 |

不包含：传送门/收集/机关目标、材料形变、碎裂粒子、布料、多关卡编辑器。
v1 是**可完整游玩的一局**：选球拍 → 发球 → 颠球增压 → 打砖 → 清版胜利 / 球尽失败。

## 2. 游戏状态机

```
Menu ──选择球拍──▶ Serve ──空格/点击──▶ Play ──球落出──▶ BallLost
                                                     │
                                     balls>0 ──▶ Serve（重新发球）
                                     balls=0 ──▶ GameOver
Play ──砖块清零──▶ Victory ──R/点击──▶ Serve（重建关卡）
GameOver ──R/点击──▶ Serve（重建关卡）
```

- **Menu**：三球拍选择（现有）。
- **Serve**：球粘在球拍上，随球拍移动；空格/点击发球。
- **Play**：物理推进 + 碰撞事件处理（球拍增压、砖块破坏）。
- **BallLost**：球 y < LOSS_Y(-80)。`balls -= 1`，更新 HUD。`balls > 0` → Serve；否则 GameOver。
- **GameOver / Victory**：DOM 覆盖层 + 重建关卡回到 Serve（保留所选球拍）。

## 3. 砖块系统

### 3.1 布局

- 8 列 × 6 行（默认 640px 宽），砖块尺寸 **56×22**，间距 4。
- **自适应布局**：列数随窗口宽度收缩（≤640px 时 3-8 列），列阵水平居中；顶行中心 y =
  窗口高度 − 28（距天花板内壁 28px，确保球可在砖顶与天花板间活动）。
- 层级模式（自下而上由软到硬，诱导玩家先颠球再打硬砖）：

| 行（自上而下编号） | 类型 | 说明 |
|---|---|---|
| 0-1（最上） | 高阻力砖 | HP2，冲击 ≥900 减 1 HP |
| 2-3 | 普通砖 | HP1，冲击 ≥800 破 |
| 4-5（最下） | 软砖 | HP1，冲击 ≥500 破 |

### 3.2 类型参数

| 类型 | HP | 破砖冲击阈值 | 颜色（渲染） |
|---|---|---|---|
| 软砖 soft | 1 | 500 px/s | 浅绿 |
| 普通砖 normal | 1 | 800 px/s | 橙 |
| 高阻力砖 hard | 2 | 900 px/s | 红 |

> 0.5.5 联动：速度上限 2000→1400（人类可接区间）。上限 1400 时 y=400 上穿冲击实测
> ~993、硬砖顶排 ~870-950，故硬砖阈值 1100→900 保持可破（探测验证三档均可破）。

- 冲击速度 = 球在本物理子步开始前的速度（`approach_speed`，与增压共用同一采样）。
- 冲击 ≥ 阈值：砖块 `hp -= 1`；`hp == 0` → 移除刚体/碰撞体，`hide_brick`，`bricks_remaining -= 1`，HUD 实时刷新。
- 冲击 < 阈值：砖块不破，球反弹（砖块 restitution 1.0，不衰减球速——符合"环境不衰减"原则）。
- **破砖时球被反射**（经典 Breakout 行为）：Rapier 碰撞事件在求解器之后触发，球先反弹、
  砖块后移除。击破不扣球速，但不会穿砖；"多砖连穿"未实现，真穿透留 v1.1。

### 3.3 碰撞事件

- 砖块碰撞体 `ActiveEvents::COLLISION_EVENTS`；`Started` 且对端是球时处理。
- 砖块为固定刚体 + cuboid 碰撞体。

## 4. 球数经济

- 初始 **5 球**。
- 球落出 `LOSS_Y` → `balls -= 1`。
- `balls == 0` 且砖块未清空 → GameOver。
- 每球重置回 Serve（球粘球拍），**速度归零**——单球生命周期重新开始（体现草案 §7）。

## 5. 目标与胜负

- **胜利**：`bricks_remaining == 0` → Victory 覆盖层。
- **失败**：`balls == 0` 且 `bricks_remaining > 0` → GameOver 覆盖层。
- 两屏均提供「重新开始」按钮 + R 键，重建关卡、球数回 5、保留球拍选择。

## 6. HUD（DOM 覆盖层）

- 顶部条：`球 ×N`、`剩余砖块 N`。
- 由 Rust 通过 web-sys 更新（外壳保持内容无关，与菜单同机制）。
- 覆盖层：GameOver / Victory（半透明背景 + 标题 + 提示）。

## 7. 渲染扩展（renderer.rs）

- 新增 `bricks: Vec<Option<Object>>`（`None` = 已破坏，不绘制）。
- API：
  - `clear_bricks()`：清空列表（重建关卡时）。
  - `add_brick(x, y, half_w, half_h, color)`：压入一个 cube Object，返回索引。
  - `hide_brick(index)`：置 `None`，绘制跳过。
  - `move_brick(index, x, y, half_w, half_h)`：resize 时按新布局重新定位（物理位置由 lib.rs 同步）。
- `render()`：逐砖绘制 cube 网格（每砖一次 draw，48 次以内，WebGPU 无压力）。
- 数据流：`lib.rs` 持有砖块物理状态与索引，渲染顺序与 `bricks` 列表一致。
- **相机取景**：target/eye 取高度 0.53/0.55（居中"球拍→砖顶"游玩区），保证默认
  与最小窗口（360×400）下砖块区完整可见（0.5.2 修正）。

## 8. 数据流总览

```
runtime.js ──key/pointer──▶ lib.rs(key/pointer_move...)
lib.rs step()：
  world.step_with_events → 碰撞事件：
    · 球-球拍 Started → 增压 ×1.30（上限 2000）
    · 球-砖块 Started → 冲击≥阈值 → 破砖（hide_brick + bricks_remaining--）
  状态迁移 → HUD 更新（DOM）
lib.rs render()：
  update_ball / update_paddle / 砖块列表 → renderer.render()
```

## 9. 收束条件（草案 §16 落地）

- **速度上限 2000 px/s**（已实现）。
- **防止永久轨道**：球低于 LOSS_Y 即丢失——天然终止无意义轨道；后续 v1.1 可加"长时间无接触环境扰动"。

## 10. 待手感实验参数

```
砖块冲击阈值（500/800/900）、球数（5）、砖块布局模式、破砖是否扣速、球拍加速（8）、
随机横向扰动（1.5%）、球速上限（1400）
```

按草案结论，这些参数以实测手感为准，代码内为常量集中管理。
